# Motion GIF · 产品动图完整方法论

> 何时读：触发 `motion-gif` 场景（产品动图/主图动效/循环 GIF）时——本文件是 16 格帧图 → 合成动图的全流程工艺。
> 方法论参考并改造自开源项目 liangdabiao/product-motion-gif（README 见 GitHub），叠加本 skill 的电商场景约束与合规要求。

## 核心机制（为什么这么做）

**不是「生成一段视频」，而是一次性画好 16 张连续画面，再按节奏连起来播放。** 每一张都由同一个模型、同一次作画完成——产品形状/颜色/光位前后一致，不会像逐帧生成那样越飘越远。这是 GPT-Image-2.5 多格帧图能力在电商的最大落点。

## 一、生成阶段（一次出 16 格帧图）

### 格数：16 格是甜点
- 格数再多 → 画面开始漂移、成本翻倍；再少 → 不够流畅
- 布局：4×4 网格，阅读顺序左→右、上→下

### 环绕参数（A 类·电商主图动效默认）
- **只转 60°，不转到背面**：起点偏左 30° → 原图 → 偏右 30°
- 方向默认从左往右；开头慢、后面快——**播完自动倒放即无缝循环**
- 产品居中不动，「转」靠背景横移体现
- 纯色底没有可滑动的东西 → 靠「主角轮廓变化」补偿，并在 prompt 里点名哪几处会变

### 分辨率：默认 2K，不上 4K
> 实测结论原话：「4K 是把 2K 放大交差的，多花 2.5 倍的钱」。除非成品需要 >500px 宽的源图。

### 试水/定稿双档位
约一半价格先跑试水档，动效满意再出定稿档——与 `model-routing.md` 的成本心智一致。

## 二、合成阶段（帧图 → 动图）

| 格式 | 何时用 | 注意 |
|---|---|---|
| **GIF** | 微信传播 / 详情页嵌入 | **无半透明**：半透明残影被压成实心色块——残影必须「用实心像素画」 |
| **WebP** | 需要透明背景 / 更高清晰度 | 更小体积、真半透明——透明素材优先 WebP |
| **MP4** | 广告投放 | 平台投放素材标准 |

- 成品宽度默认 500-640px；**文件控制在 3MB 内**（微信传播硬约束）
- 合成工具链：切片（4×4 网格裁切）→ 按序循环（正放+倒放=无缝）→ 压缩
- 切片可参考生态的 image-grid-slicer 类工具（浏览器本地切片，不出网）

## 三、五类动效（A 类是电商主场）

| 类别 | 动什么 | 给不给参考图 | 用途 |
|---|---|---|---|
| **A 环绕展示（默认）** | 镜头绕主体转 60°、背景横移 | 要给 | 电商主图、详情页首图、单品立体展示 |
| B 角色动作 | 主体打招式、背景不动 | 可不给 | 游戏角色（非本 skill 主场） |
| C 速度型动作 | 主体动作+背景后掠 | 可不给 | 飞行奔跑 |
| C2 像素风/透明底 | 同 C + 街机像素+透明背景 | 可不给 | 游戏素材 |
| D 表情包 | 一张脸表情连续变化 | 要给人脸 | 表情包（注意肖像权红线） |

## 四、效果排查九条（出图不对时逐条对）

1. **出现不该有的东西** → 参考图的角色没说清（Image N: role 分配缺失）
2. **越转越变形** → 背景太乱 / 主体太多
3. **只晃不转** → 没点名主角 / 纯色底无背景可滑
4. **抖动** → 机位没锁死（prompt 里写 camera fully locked）
5. **帧间产品不一致** → 没写 "identical to reference image across ALL 16 frames"
6. **节奏不匀** → 没写缓入（slow at start, faster at end）
7. **循环有跳帧** → 倒放合成缺失或首尾帧不衔接
8. **透明残影变实心** → GIF 格式限制，换 WebP
9. **文件超 3MB** → 降宽度（500-640px）或减帧（16→12）

## 五、与 skill 工作流的衔接

- **触发**：`scenarios/motion-gif.json`（Step 2 路由命中）
- **模型**：sunburst（16 帧跨格一致性是精修能力，flare 易漂移）
- **生成**：imagegen.sh 走 api 模式出帧图网格；切片/合成是本地后处理（Claude 用 Python PIL 完成切片+GIF/WebP 合成，不依赖外部服务）
- **合规**：动图同样带 C2PA 标记；平台对主图动图（如 Amazon 主图视频位）有各自规范，投放前查 `platform-constraints.md`
